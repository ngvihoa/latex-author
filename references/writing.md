# Writing and evidence

For experimental reports, collect the task, dataset and split, method, configuration, evaluation protocol, results, and limitations from actual artifacts. Keep a small source-to-claim map in working notes when multiple runs or sources might be confused. Record run identifiers and provenance there; put only reader-relevant detail in the report.

Check that metrics refer to the same dataset split, model checkpoint, units, and aggregation. Recompute derived percentages when inputs exist. Do not compare incomparable protocols without explaining the difference. A missing experiment stays missing; an expected result is not an observed result.

Use verified bibliographic records from supplied sources or authoritative publications. Confirm title, author, date, identifier, and the claim supported. Do not invent a DOI or use a citation solely because its title sounds relevant. Network verification depends on the tools available to the invoking agent; disclose any unverified metadata.

For Vietnamese, use UTF-8 source and check diacritics in text, headings, captions, and extracted PDF text. Keep technical terminology consistent. For English, use the requested variety and tone. Do not force bilingual sections unless requested.

A useful experimental report may include introduction, method, setup, results, discussion, and conclusion. A technical document may instead need architecture, usage, constraints, and operations. Follow the actual audience and supplied rubric.
